# Initial Discovery
## 1. Facts
#
### - organizers spend a lot of time matching volunteers to activities.
### - Volunteers are sometimes unsure which activities need help.
### - organizers do not always know who is available.
### - Changes and cancellations can be difficult to communicate.
### - Some activities require particular skills or experience.
### - organizers need to know who is attending each activity.
### - Volunteer information is currently stored in several places.
### - Accessibility and privacy need to be considered.
### - volunteers sign up using email, phone calls, spreadsheets and paper forms.
### - The organization runs local event and activities throughout the year.
#
#
#
## 2. Assumptions
### - we assume that there is a manager for organizing activities.
### - we assume that organizers manage cancellations and changes of an event and activity.
### - we assume that skills and experience are not known with each volunteer.
### - we assume an organizer is managing all volunteering sign ups.
### - We assume an organizer is managing cancellations and changes within the events and activities.
### - we assume there are multiple activities on at the one time.
#
#
#
## 3. Unknowns
### - who can register?
### - what happens when a cancellation happens?
### - where is volunteer information is stored exactly?
### - how many attends each activity?
### - what sort of skill or experience is required?
### - how do organizers know who is attend each activity?
### - what sort of accessibility and privacy is needed for the system software.
#
#
#
## 4. Stakeholders
### - Volunteers.
### - Organizers.
### - Event manager.
### - Activity manager.
### - Director of the organisation.
### - Sign up manager.
### - I.T admin
#
#
#
## 5. Goals
### - The system should organize all information to one location and set into separate area within the location.
### - The system show have the needed accessibility and privacy.
### - the system should be be able to match volunteers to activities with relevant experience and/or skills in a timely manner.
### - The system should allow registration to only be made on it.
#
#
#
## 6. Scope
### - The system will have all information for the volunteers including their experience and skills and availability stored in one area.
### - 6.	The system will allow organisers to create events and activities.
### - The system will update all volunteer information in what skills or experience they have done.
#
#
#
## 7. Candidate Requirements
### - the system will have volunteers receive event and activities reminders.
### - the system will have an organisers that can accept or reject volunteers joining an event or activity
### - the system will have an availability slot for organizers to know which volunteer is available.
### - the system will have organised volunteer information stored in one location.
#
#
### - the system will have appropriate accessibility.
### - the system will have appropriate privacy.
